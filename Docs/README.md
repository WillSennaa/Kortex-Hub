### 🎯 Requisitos Funcionais (Detalhes Expandidos)

* **RF01 - Gerir Utilizadores:** O sistema deve permitir cadastrar, consultar, atualizar e desativar contas de usuários. A gestão de usuários diferencia Usuários Comuns de Administradores, sendo que os administradores possuem permissões extras para gerenciar categorias globais e emitir avisos. Os dados essenciais de autenticação ficam armazenados de forma remota no Supabase (PostgreSQL).
* **RF02 - Autenticar Acesso:** A entrada no aplicativo é validada utilizando e-mail e senha, possuindo suporte para recuperação de credenciais. O acesso às funcionalidades internas exige a validação de um token JWT emitido pela Web API em C#. Além disso, a troca de senha ou alteração de e-mail exige o envio prévio de um código de verificação para o e-mail do usuário.
* **RF03 - Visualizar Central:** O aplicativo deve apresentar um Dashboard inicial estruturado em formato de calendário ou linha do tempo. O usuário pode alternar facilmente os dias da semana ou do mês no carrossel superior.
* **RF04 - Centralizar Dados:** O Dashboard consolida e exibe de forma unificada as tarefas do dia, os treinos agendados e o resumo financeiro atual. Essa interface atualiza todos os blocos de dados dinamicamente e em tempo real, refletindo o estado exato das pendências da data selecionada no calendário.
* **RF05 - Gerir Finanças:** O sistema permite registrar entradas e saídas contendo valor, data e descrição. Para manter a organização, toda transação financeira deve obrigatoriamente ser vinculada a uma Conta/Carteira e a uma Categoria. O saldo exibido nas telas é calculado de forma dinâmica subtraindo as saídas registradas das entradas.
* **RF06 - Categorizar Transações:** O aplicativo possibilita vincular receitas e despesas a categorias específicas. Para facilitar a rápida identificação visual na interface, as categorias financeiras e as contas possuem um código de ícone e uma cor em formato hexadecimal (#HEX). Para garantir a integridade dos dados locais, o sistema impede a exclusão de categorias que já possuam transações vinculadas sem antes realizar uma reatribuição ou arquivamento.
* **RF07 - Gerir Rotinas de Treino:** As rotinas de treino podem ser estruturadas por divisões customizadas (como Treino A e Treino B). Cada rotina possui uma estrutura hierárquica e pode ser agrupada em pastas temporais ou temáticas (ex: "Jan - Mar/2026") para facilitar a visualização ao longo dos meses.
* **RF08 - Registar Exercícios:** O sistema permite adicionar exercícios dentro dos treinos, registrando o histórico de cargas, séries, repetições e tempo de descanso. O histórico de carga e execução fica isolado e restrito ao treino do usuário, mantendo o catálogo global de exercícios intacto. Para exercícios com peso corporal ou alongamentos, o sistema aceita que o campo de carga receba valor zero ou nulo.
* **RF09 - Gerir Tarefas (To-Do):** É possível criar listas para atividades fora da rotina contendo título, descrição e prazo de conclusão. As tarefas podem ser classificadas com prioridade (Baixa, Média ou Alta) e agrupadas dentro de pastas de projetos específicos, como "Faculdade" ou "Trabalho".
* **RF10 - Concluir Atividades:** O usuário pode marcar visualmente e arquivar as tarefas concluídas. Caso necessário, as tarefas podem ser desmarcadas e retornar ao status pendente a qualquer momento. O cabeçalho deste módulo fornece métricas de progresso diário, calculando e exibindo a porcentagem das tarefas que já foram finalizadas naquele dia.
* **RF11 - Exportar e Importar Backup Local:** O utilizador pode gerar um arquivo cifrado contendo todo o seu histórico operacional. Atuando como uma solução de portabilidade, o aplicativo permite que o usuário faça o upload desse arquivo criptografado de banco de dados diretamente para o seu Google Drive pessoal, mantendo a responsabilidade e privacidade integral dos dados.

### 🛡️ Requisitos Não-Funcionais (Detalhes Expandidos)

* **RNF01 - Desempenho de Interface:** O aplicativo deve oferecer uma navegação muito fluida e transições de telas rápidas sem engasgos. Toda a arquitetura visual foi projetada com atalhos rápidos e de fácil acesso, modularizados através de um Guia de Estilos no Figma, permitindo uma usabilidade ágil para o cadastro de rotinas.
* **RNF02 - Segurança de Dados:** As senhas devem ser obrigatoriamente criptografadas, impedindo a exposição de informações sensíveis e atendendo às diretrizes da LGPD. A senha jamais é salva em texto puro no banco Supabase, passando sempre por um processo de hash seguro com *salt* (ex: BCrypt ou Argon2) gerenciado exclusivamente pelo backend.
* **RNF03 - Arquitetura de Software:** O projeto seguirá padrões arquiteturais maduros (como Clean Architecture ou MVC) para facilitar manutenções futuras e demonstrar qualidade de código no portfólio de ADS. A infraestrutura é híbrida, utilizando uma Web API em C# (ASP.NET Core) para regras de negócio remota.
* **RNF04 - Persistência Local (Offline-First):** Para garantir funcionamento estável, alta velocidade e consultas imediatas, os dados cotidianos devem ser salvos localmente. Utilizando SQLite ou WatermelonDB, tabelas de domínio operacionais (como tarefas, treinos e finanças) operam de forma 100% offline no dispositivo móvel do usuário. Além disso, para evitar conflitos locais, todas as entidades utilizam o padrão universal de UUID v4 como Chave Primária.
